# Configuration

Memo uses `config.toml` to manage provider selection, per-model overrides, and MCP servers.
This page focuses on what each key means and how Memo resolves model behavior at runtime.

## Config File Location

Default:

- `~/.memo/config.toml`

When `MEMO_HOME` is set:

- The config path becomes `$MEMO_HOME/config.toml`

## How Configuration Is Applied

Memo applies configuration in this order at runtime:

1. Selects the active provider via `current_provider`.
2. Reads that provider's `model`.
3. Resolves model-level overrides from `model_profiles`.
4. Resolves the session context window from the `context_window` policy.

Switching models in the TUI with `/models` re-runs this resolution for the selected provider/model.

## Provider Configuration

### Minimal Example

```toml
current_provider = "deepseek"

[[providers.deepseek]]
name = "deepseek"
env_api_key = "DEEPSEEK_API_KEY"
model = "deepseek-chat"
base_url = "https://api.deepseek.com"
```

### Multiple Providers

```toml
current_provider = "deepseek"

[[providers.deepseek]]
name = "deepseek"
env_api_key = "DEEPSEEK_API_KEY"
model = "deepseek-chat"
base_url = "https://api.deepseek.com"

[[providers.openai]]
name = "openai"
env_api_key = "OPENAI_API_KEY"
model = "gpt-4.1-mini"
base_url = "https://api.openai.com/v1"
```

### Provider Keys

- `current_provider`
    - Default provider name for new sessions.
    - Must match a configured provider `name`.
- `providers.<name>.name`
    - Provider identifier shown in `/models`.
- `providers.<name>.env_api_key`
    - Name of the environment variable used as the first-priority API key lookup.
- `providers.<name>.model`
    - Model ID sent to the upstream API.
- `providers.<name>.base_url` (optional)
    - OpenAI-compatible endpoint.
    - Useful for custom gateways or compatible providers.

## Model Configuration (Overrides)

Memo uses conservative defaults for model capabilities, controlled by local `config.toml` overrides:

```toml
[model_profiles.gpt-5]
supports_parallel_tool_calls = true
supports_reasoning_content = true
context_window = 272000

# Provider-specific override; key format: "<provider>:<model>"
[model_profiles."openai:gpt-5"]
supports_parallel_tool_calls = false
```

### Supported Fields

- `supports_parallel_tool_calls`
    - Controls whether Memo sends `parallel_tool_calls`.
- `supports_reasoning_content`
    - Controls whether reasoning content is carried into follow-up turns after tool calls.
- `context_window`
    - Hard prompt/context limit used by the Memo runtime for the session.
    - Must be a positive number.

### Key Formats

- `[model_profiles.<model>]`
    - Model-level override; applies to all providers using this model name.
- `[model_profiles."provider:model"]`
    - Provider-specific override; applies to one provider + model pair.
    - Quoted because the key contains `:`.

Examples:

- `[model_profiles.gpt-5]` applies to any provider using `gpt-5`.
- `[model_profiles."openai:gpt-5"]` applies only when the provider is `openai` and the model is `gpt-5`.

## Context Window Policy

The session context window resolves with this priority:

1. `model_profiles."provider:model".context_window`
2. `model_profiles."<model>".context_window`
3. Default `1000000`

Memo applies this setting at startup and re-applies it when you switch models with `/models`.

### Practical Example

```toml
[model_profiles.gpt-5]
context_window = 272000

[model_profiles."openai:gpt-5"]
context_window = 128000
```

Results:

- `openai:gpt-5` -> `128000`
- Other providers using `gpt-5` -> `272000`
- Any model without a `context_window` override -> `1000000`

## Context Compaction

Long sessions are compacted automatically when context usage exceeds a threshold:

```toml
auto_compact_threshold_percent = 90 # default: 90 (1-100)
```

- Valid range is `1` to `100`; invalid values fall back to `90`
- Compaction summarizes earlier context and continues the session, keeping it usable
- Use `/compact` to compact manually at any time

## MCP Server Configuration

### OAuth Settings (Remote Servers)

```toml
# Local port for the OAuth browser callback (optional)
mcp_oauth_callback_port = 38433

# Credential storage: "auto" (default) / "keyring" / "file"
mcp_oauth_credentials_store_mode = "auto"
```

- `mcp_oauth_callback_port`: fixed callback port used by `memo mcp login`; an available port is picked automatically when unset.
- `mcp_oauth_credentials_store_mode`: where OAuth tokens are persisted.

### Local Stdio MCP

```toml
[mcp_servers.local_tools]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/your/path"]
# Optional
# type = "stdio"
# stderr = "inherit" # or "pipe" / "ignore"
# [mcp_servers.local_tools.env]
# FOO = "bar"
```

### Remote Streamable HTTP MCP

```toml
[mcp_servers.remote]
type = "streamable_http"
url = "https://your-mcp-server.com/mcp"
bearer_token_env_var = "MCP_TOKEN"
# Optional custom headers
# http_headers = { "X-Team" = "platform" }
# or headers = { "X-Team" = "platform" }
```

## Managing MCP with the CLI

```bash
memo mcp list
memo mcp get <name>
memo mcp add <name> -- <command...>
memo mcp add <name> --url <url> --bearer-token-env-var <ENV_VAR>
memo mcp remove <name>
```

Also available:

```bash
memo mcp help
```

`streamable_http` MCP servers support OAuth login/logout:

```bash
memo mcp login <name> [--scopes read,write]
memo mcp logout <name>
```

## Runtime Environment Variables

### Required for Model Calls

- `<provider.env_api_key>`: environment variable name configured on the provider, used as the first-priority API key lookup.
- `OPENAI_API_KEY`: fallback API key when the provider-specific key is missing.
- `DEEPSEEK_API_KEY`: fallback API key when both the provider-specific key and `OPENAI_API_KEY` are missing.

### Commonly Used Optional

- `MEMO_HOME`: overrides the Memo home directory.

## Skills Discovery

Memo discovers agent skills (`SKILL.md`) automatically at startup and attaches the available skill metadata to the runtime system prompt.

### Discovery Roots

- Project scope: `.<agent>/skills` directories at the project root (e.g. `.agents/skills`, `.claude/skills`, `.codex/skills`)
- User scope: `$MEMO_HOME/skills` (or `~/.memo/skills`)
- Not scanned: hidden `~/.xxx/skills` directories outside the Memo home directory

### Minimal `SKILL.md`

```md
---
name: doc-writing
description: Generate and update technical documentation.
---

# Doc Writing
```

Memo reads the `name` + `description` frontmatter and exposes each discovered skill to the model:

- `- <name>: <description> (file: <absolute-path-to-SKILL.md>)`

You can invoke a skill explicitly by mentioning `$skill-name` in a prompt (e.g. `$doc-writing`).

### Default Active Skills

You can persist the default set of active skills:

```toml
# Unset: all discovered skills are active by default
# []: no skills active by default
active_skills = [
  "/absolute/path/to/.codex/skills/doc-writing/SKILL.md"
]
```

`active_skills` stores absolute paths to `SKILL.md` files.

### Advanced Tool / Runtime Switches

- `MEMO_SHELL_TOOL_TYPE`: `unified_exec` (default) / `shell` / `shell_command` / `disabled`.
- `MEMO_FS_ALLOWED_ROOTS`: additional roots the filesystem tools may access, comma-separated.
- `MEMO_ENABLE_MEMORY_TOOL=0`: disable `get_memory`.
- `MEMO_ENABLE_COLLAB_TOOLS=0`: disable subagent tools.
- `MEMO_SUBAGENT_COMMAND`: command used to spawn subagents.
- `MEMO_SUBAGENT_MAX_AGENTS`: maximum concurrent subagents (default `4`).
- `MEMO_TOOL_RESULT_MAX_CHARS`: maximum characters kept from a single tool result before it is elided.
- `MEMO_SANDBOX_WRITABLE_ROOTS`: comma-separated absolute paths appended to the write sandbox roots of local write tools.

### MCP Config Authentication

- `<bearer_token_env_var>`: when set on an MCP server config, Memo reads this environment variable and injects `Authorization: Bearer <token>` for that server.

### Notes

- `SHELL`, `USER`, and `USERNAME` are system environment variables read as runtime fallbacks; they are not Memo-specific feature switches.
