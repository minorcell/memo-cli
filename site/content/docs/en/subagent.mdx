# Multi-Agent (Subagent)

Subagents let Memo split large tasks into smaller parallel jobs and collect results back into the main session.

## What Subagents Are

A subagent is a child Memo run created by the current session to execute a scoped task.

Subagent tool family:

- `spawn_agent`
- `send_message`
- `followup_task`
- `wait_agent`
- `interrupt_agent`
- `list_agents`

## When to Use

Good use cases:

- parallel audits across multiple folders
- independent investigations (errors, tests, logs)
- large tasks that can be decomposed cleanly

Not ideal:

- tiny single-file edits
- tasks requiring strict step-by-step dependency

## Enable / Disable

Enabled by default.

Disable all subagent tools:

```bash
export MEMO_ENABLE_COLLAB_TOOLS=0
```

Common tuning:

```bash
export MEMO_SUBAGENT_COMMAND="memo --dangerous"
export MEMO_SUBAGENT_MAX_AGENTS=4
```

Defaults:

- max concurrent running subagents: `4`
- spawn command:
    - `MEMO_SUBAGENT_COMMAND` if set
    - otherwise `node <cwd>/dist/index.js --dangerous` if `dist/index.js` exists
    - otherwise `memo --dangerous`

## Lifecycle

Typical flow:

1. `spawn_agent` to create an agent and start its first submission.
2. `wait_agent` to wait for activity until the agent reaches a final status.
3. `followup_task` to send follow-up work (starts a turn if the agent is idle).
4. `send_message` to queue a message without starting a turn.
5. `interrupt_agent` to interrupt a running turn while keeping the agent available.

## Behavior Notes

### `spawn_agent`

- requires `message` and `task_name`; optional `agent_type` and `fork_turns`
- starts immediately with `message`
- fails if the running-agent count reaches `MEMO_SUBAGENT_MAX_AGENTS`

### `send_message`

- queues a message for an agent without starting a turn

### `followup_task`

- sends follow-up work and starts a turn if the target agent is idle

### `wait_agent`

- `timeout_ms` is clamped to `10s` to `300s`
- default timeout is `30s`
- child result content is delivered separately to the next model request
- returns `timed_out=true` if nothing happened before the timeout

### `interrupt_agent`

- interrupts the agent's current turn
- keeps the agent available for follow-up work

### `list_agents`

- lists live sub-agents in the current agent subtree
- optional `path_prefix` to narrow the listing

## Status Values

Main statuses:

- `pending_init`
- `running`
- `interrupted`
- `completed`
- `errored`
- `shutdown`

## Safety

Subagent tools are auto-approved by default, so task scoping matters.

Recommended:

- keep prompts specific and bounded
- set clear deliverables per subagent
- close unused agents to reduce noise and resource usage
